# 2026-07-10 Flutter Gradle + SDL3 Runtime Host Step

## Scope

- Writable project remains `/root/kiriki-work/KiriKiri-LauncherC` only.
- Target remains Flutter + SDL3 with gradual Cocos removal.
- Fixed game surface remains `1920x1080`; do not resize game output to physical screen size.

## Flutter Embedding / Gradle Changes

- `platforms/android/settings.gradle` now resolves Flutter SDK from `platforms/android/local.properties` `flutter.sdk`, `FLUTTER_ROOT`, or `FLUTTER_HOME`, and includes Flutter's Gradle build at `packages/flutter_tools/gradle`.
- `platforms/android/settings.gradle` includes Flutter's Gradle build directly; the plugin loader was not applied because it conflicts with the legacy Android root Kotlin plugin classpath.
- `platforms/android/app/build.gradle` applies `dev.flutter.flutter-gradle-plugin` and points `flutter { source '../../../flutter_launcher' }` at the real Flutter module.
- `platforms/android/gradle.properties` sets `skipDependencyChecks=true` because the legacy Compose launcher still pins Kotlin 1.9.x while the current Flutter tool warns/errors below Kotlin 2.0. This is a temporary compatibility bridge until the Compose/Cocos launcher code is retired or migrated.
- The previous manual `flutter.jar` wiring was removed. It was not enough because `GeneratedPluginRegistrant` and Flutter assets are generated by Flutter tooling, not by the raw engine jar.
- `platforms/android/app/AndroidManifest.xml` now declares `flutterEmbedding=2` under `<application>`.

## SDL Runtime Default

- `LauncherPrefs.getUseSdlRuntimeActivity()` now defaults to `true`.
- Flutter fallback settings now default `useSdlRuntimeActivity` to `true` in:
  - `flutter_launcher/lib/src/bridge/launcher_bridge.dart`
  - `flutter_launcher/lib/src/pages/launcher_home_page.dart`
- Android Gradle now defaults `krkr2NoCocosHost=true`, so native Gradle builds pass `-DKRKR2_ENABLE_COCOS_HOST=OFF` unless overridden with `-Pkrkr2NoCocosHost=false`.
- CI Flutter shell generation also defaults `krkr2NoCocosHost=true`.
- Cocos Java dependency and `MainActivity` are intentionally still present for compile/fallback compatibility. Do not delete them yet.

## SDL3 Frame Ownership Step

- `AndroidRuntimeBridge.runFrame()` no longer accepts a Java-computed delta. Kotlin still uses Choreographer as a cadence signal, but native owns delta calculation.
- `TVPAndroidSDLRuntimeHost` now has `RunFrameTick()` and an internal steady-clock frame delta.
- `TVPAndroidSDLRuntimeHost::RunFrameTransaction()` owns the single frame transaction:
  - ensure Android SDL render context current
  - `TVPRuntimeRunApplicationFrame(delta)`
  - `TVPRuntimeRecycleFrameResources()`
  - `TVPRuntimePumpScreenPresenter(stage)`
- Frame clock resets after game start and on SDL runtime resume/surface-created lifecycle events.
- Cocos renderer `nativeFrameEnd` now pumps presenter only when `KRKR2_ENABLE_COCOS_HOST` is enabled.

## Presenter Safety Fixes

- All weak Flutter surface bridge hooks are now checked before use, including `TVPSDLAndroidFlutterPresenterTryPresentSurface()`.
- EGL/GL presenter changes from the previous step remain: save state before first program creation, restore failure no longer queues a dirty frame, and `uUvRect` groundwork remains.

## Remaining Risks

- `SdlRuntimeActivity` is still a plain `Activity`, not `SDLActivity`. SDL Java static surface assumptions remain a migration risk until the SDL3 host no longer depends on SDL Java window creation.
- The Android no-Cocos native path still keeps Java Cocos classes to compile fallback code. Full removal requires replacing `KR2Activity`/`NativeUiHost` dependencies.
- Visual artifacts on native GL path still likely involve padded texture UV origin/FBO semantics (`uv=0.9375,0.5273` in logs), not the software path.

## Validation

- `git diff --check` passed after these edits.
- Full Android build still depends on local Android SDK/NDK configuration. CI should be used for full verification.
